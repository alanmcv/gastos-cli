# gastos-cli — Spec Driven Development

CLI en Python para que un estudiante registre sus gastos y vea resúmenes por categoría.

## Reglas
1. No escribas código hasta que el usuario lo pida explícitamente.
2. Antes de cada paso, lee `docs/constitution.md` y la spec correspondiente en `docs/specs/`.
3. Sigue este flujo obligatorio, sin saltarte etapas: constitución → spec → plan → tasks → implementación.
4. No avances a la siguiente etapa sin la aprobación del usuario.
5. Implementa una sola tarea a la vez: primero escribe los tests que fallan, luego el código mínimo que los hace pasar.
6. Al terminar una tarea, ejecuta los tests, marca la tarea como completada y detente.
7. Si la spec es ambigua o contradice la constitución, pregunta antes de suponer.
8. Responde y escribe todo en español (documentos, comentarios, mensajes de commit).

## Artefactos
- `docs/constitution.md` — principios y restricciones del proyecto.
- `docs/specs/<feature>/spec.md`, `plan.md`, `tasks.md` — uno por funcionalidad.
